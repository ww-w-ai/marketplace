# 소개서 디자인 시스템을 정의하는 법

[English](design-system-guide.md) | 한국어

권위: 재사용 가능한 제작 가이드. 기본 샘플의 미학은 제안이며, 고객의 승인된 시안·브랜드 규칙이 우선합니다.

## 먼저 기준 장표를 정한다

표지, 정보가 많은 본문, 실제 화면이 들어간 증거 장표를 기준으로 삼습니다. 세 장에서 반복되는 규칙을 추출합니다. 한 장에만 있는 장식은 공통 규칙으로 올리지 않습니다. 먼저 한 문장으로 방향을 적습니다. 예: "따뜻한 밝은 바탕, 짙은 글자, 노란 강조 면과 청록 포인트로 명확한 운영 흐름을 설명한다."

## 1. Foundations: 값을 채운다

| 결정 | 기본 샘플 | 바꾸는 기준 |
|---|---|---|
| 기본 배경 / 표면 | `#FFFEFA` / `#F8F5EB` | 브랜드의 차갑고 따뜻한 정도 |
| 본문 / 보조 글자 | `#151208` / `#5A5340` | 축소해도 읽히는 명도 차 |
| 핵심 포인트 / 강조 면 | `#005E57` / `#FFDC3D` | 역할이 겹치지 않는 포인트 색 |
| 폰트 | Pretendard 400/700/900 | 한국어·숫자 가독성, 로컬 포함 라이선스 |
| 표지 / 제목 / 소제목 | 132 / 80 / 44px | 가장 긴 실제 문장으로 시험 |
| 본문 / 보조 / 라벨 | 32 / 24 / 22px | 16:9 화면 축소 시 읽히는 크기 |
| 캔버스 / 안전 여백 | 1920×1080 / 72px | 이 엔진의 고정 캔버스 유지 |
| 본문 시작 / 하단 여유 | y290 / 150px | 제목·본문·푸터 충돌 방지 |
| 간격 | 8 / 16 / 24 / 32 / 48 / 72px | 그룹 안보다 그룹 사이를 넓게 |
| 모서리 / 그림자 | 24px / `0 18px 48px #15120812` | 증거 이미지·카드의 같은 질감 |
| 레이어 | art 0 / content 1 / note 2 | 텍스트가 그림 위에 오도록 |
| 모션 | 엔진 전환만, reduced-motion에서 제거 | 정적 출력이 항상 완전해야 함 |
| 아이콘 | 단순 선형, 텍스트 색 상속 | 장표마다 다른 화풍 혼합 금지 |

색은 먼저 역할로 이름을 붙입니다. `--yellow`보다 `--accent`, `--dark-green`보다 `--primary`가 브랜드 교체에 유리합니다. 색 공간은 필요하면 OKLCH로 바꿀 수 있지만 현재의 hex 값을 근거 없이 근사치로 변환하지 않습니다. 작은 글자 대비 목표는 4.5:1, 큰 제목은 3:1입니다. 장식용 밝은 색을 작은 본문색으로 사용하지 않습니다.

장표 안에서 앱처럼 반응형으로 재배치하지 않습니다. 캔버스 전체가 화면에 맞춰 축소됩니다. 휴대폰에서 작게 보이면 별도 읽기용 자료를 설계해야 합니다.

## 2. Components: 반복되는 문법을 정한다

| 컴포넌트 | 구성 / 역할 | 기본 규칙 |
|---|---|---|
| TitleBlock | eyebrow + title + lead | 한 장 한 주장, 제목 두 줄이면 lead 위치 조정 |
| Card | ordinal + heading + body | 같은 페이지에서 같은 높이와 내부 여백 |
| Evidence | 실제 캡처 + 설명 | 이미지 비율 유지, 수치 변조 금지 |
| Process | 단계 카드 + 연결선 + 되먹임 설명 | 순서와 방향을 글자로도 설명 |
| Comparison | 기준 + 같은 항목의 선택지 | 각 열의 측정 기준을 통일 |
| ArtLayer | 텍스트 없는 그림 + 별도 텍스트 | 그림 속 제목/라벨은 제거 |
| Footer | 브랜드 + 페이지 번호 | 번호는 빌더가 자동 처리 |

각 컴포넌트에 "언제 쓰는지, 어떤 토큰을 쓰는지, 최대 분량, 변형"을 기록합니다. 표지는 cover 변형, 본문은 기본 변형만으로 시작합니다. 상태가 없는 정적 카드에 앱용 hover/loading 상태를 추가할 필요는 없습니다. 편집/선택/인쇄 상태는 기존 엔진이 담당합니다.

## 3. Patterns: 장표 유형을 정한다

표지 → 핵심 주장, 3열 본문 → 병렬 이유, 증거 → 실제 화면과 해설, 프로세스 → 단계적 변화, 비교 → 같은 기준의 차이, 아트 → 강한 시각 메시지. 표를 보여줘야 하는 페이지를 억지로 카드로 바꾸지 않습니다. 모든 페이지를 같은 레이아웃으로 만들기보다 제목·여백·색 역할을 같게 유지합니다.

## 4. Guidelines: 제작 판단을 남긴다

제목은 결론, 본문은 근거, 캡션은 출처나 필요한 맥락입니다. 요청하지 않은 배지·영문 라벨·출처 장식은 넣지 않습니다. 실제 화면을 생성형 그림으로 대체하지 않습니다. 원본 데이터와 설명 문장을 분리하고, 검증되지 않은 수치를 만들어 넣지 않습니다.

시안과 최종 HTML을 같은 크기로 비교합니다. 긴 제목·긴 회사명·표의 긴 셀을 넣어 잘림을 확인합니다. 텍스트를 줄이거나 레이아웃을 바꾼 뒤에만 글자 크기를 조정합니다. page별 !important 덧붙이기로 해결하면 공통 규칙이 무너집니다.

## 문서에서 코드로

`docs/design-system.md`에 결정과 이유를 기록하고 `html/theme.css`에 값을 넣습니다. `components.css`는 역할별 토큰을 참조합니다. 좌표 예외는 `pages.css`의 페이지 ID 아래에 둡니다. 실제 예제와 안티패턴은 [CSS 가이드](css-customization.ko.md)에 있습니다.

브랜드 변경 검토 순서는 표지 → 본문 → 증거 → 나머지 페이지입니다. HTML 색을 바꿔도 이미 생성된 그림 속 색은 바뀌지 않으므로, 이미지 프롬프트와 배경 자산도 새 브랜드에 맞춰 다시 검토합니다.
