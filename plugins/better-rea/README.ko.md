# better-rea

[English](./README.md) · 한국어

**컴파일된 앱을 두고 에이전트가 하는 모든 주장을 증거로 입증하게 하거나, 아니면 "unknown"으로 남기게 하는 Claude Code 스킬.**

REA(Reverse Engineer Anything)는 에이전트를 실제 분석 엔진에 연결합니다 — 네이티브 바이너리에는 Ghidra, Electron·웹 앱에는 자바스크립트 분석. 소스 없이 빌드 결과물만 있는 앱의 내부를 들여다볼 수 있게 해주죠. 그런데 REA만 붙여서 "이거 어떻게 돌아가?"라고 물으면, 읽기엔 그럴듯하지만 상당 부분은 지어낸 답이 나옵니다. 에이전트가 증거를 조금 꺼내다가 나머지를 같은 자신만만한 어조로 메꿔버리거든요. 그 결과는 그냥 모델한테 맡겼을 때와 결정적으로 다르지 않았습니다. 차이를 만든 건 엔진이 아니라 쓰는 방식이었어요. `better-rea`는 테스트에서 실제로 결과를 끌어올린 세 가지 — 증거·한계 루프, 고정된 보고서 템플릿, 도메인 방법 노트 — 로 REA를 감싸고, 없거나 반증된 주장을 인용한 보고서를 실패 처리하는 검증기 `scripts/check-ledger.mjs`를 함께 싣습니다.

아래 세 가지가 스킬이 REA 위에 더하는 것입니다. 검증기는 그 규율을 '에이전트가 말로 넘어갈 수 있는 제안'이 아니라 '결과물이 반드시 통과해야 하는 관문'으로 만드는 부분이고요.

| 구성 | 하는 일 | 위치 |
|---|---|---|
| 루프 | 모든 결론은 구체적 증거(함수 이름, `file:line`, 디스어셈블리 줄, 호출 경로)와 한계를 단 주장이다. 확인될 때까지 다시 파고, 닿지 못한 것은 "unknown"으로 남긴다. | `references/loop.md` |
| 템플릿 | 고정된 보고서 형식 — 관찰, 가설, 증거, 실제 메커니즘, 재현 — 에서 '실제 메커니즘'의 모든 줄이 '증거'의 한 줄로 이어진다. | `assets/report-format.md` |
| 도메인 노트 | 이런 종류의 앱은 메커니즘이 보통 어디에 있는지에 대한 방법 노트. 에이전트가 처음 걸린 것 말고 중요한 경로를 따라가게 한다. | `references/methods.md` |
| 강제 | 원장에 없거나 반증된 주장을 인용하면 검증기가 0이 아닌 코드로 종료한다. | `scripts/check-ledger.mjs` |

## REA만으로는 왜 부족한가

빌드된 앱만 있고 소스는 없습니다. REA를 붙인 에이전트에게 구조를 설명해 달라고 하면, 깔끔한 다이어그램과 이름 붙은 모듈, 기능이 어떻게 도는지에 대한 자신만만한 설명이 돌아옵니다.

그런데 확인해 보면 모듈 이름은 추측이고, 데이터 흐름은 '그런 류의 앱이 보통 하는 것'이지 '이 앱이 실제로 하는 것'이 아닙니다. 함수도, 주소도, 디스어셈블리 한 줄도 가리키지 않아요. 분석 엔진은 바로 거기 있었는데, 규율이 없었던 겁니다. 에이전트가 증거를 꺼내다 중간에 멈추고, 그 빈칸을 사실처럼 써버린 거죠.

여러 구성으로 테스트해보니, REA를 그냥 붙이는 것만으로는 모델에 맡긴 것을 결정적으로 넘지 못했습니다. 리프트는 세 가지에서 왔고, 그것도 셋이 함께 적용됐을 때만 났어요.

## better-rea가 더하는 것

**1. 증거·한계 루프.** 모든 결론은 원장(ledger)에 주장으로 적는다. 주장에는 분석에서 나온 구체적 증거 — 실제 함수 이름, `file:line`, 디스어셈블리 줄, 호출 경로 — 가 필요하고, 없으면 쓰지 않는다. 모든 주장은 무엇을 입증하지 못했는지 밝히고, 분석이 닿지 못한 것은 "unknown"으로 남긴다. 필요한 주장이 확인될 때까지 분석을 다시 돌린다.

**2. 고정된 보고서 템플릿.** 보고서는 원장에서 하나의 형식으로 조립된다.

```text
관찰(Observed behavior)     밖에서 보이는 앱의 동작
가설(Hypotheses)            검토한 후보 설명 — 틀린 것까지
증거(Evidence)              위치를 단 원장 항목
실제 메커니즘(Actual)        결론 — 모든 문장이 '증거'의 한 줄로 이어진다
재현(Reproduce / verify)    다른 사람이 돌려 확인할 수 있는 절차
```

**3. 도메인 방법 노트.** 이런 종류의 앱은 메커니즘이 보통 어디에 사는지에 대한 노트를 스킬이 들고 있어, 에이전트가 처음 디스어셈블한 것 말고 중요한 경로를 따라가게 한다.

내보내기 전, 검증기가 보고서를 원장과 대조합니다.

```bash
node scripts/check-ledger.mjs ledger.md --deliverables report.md
```

원장에 없거나 분석 중 반증된 주장을 인용한 문장이 있으면 결과물을 실패 처리합니다. 통과하지 못한 보고서는 완성이 아닙니다.

## 사용

설치한 뒤에는 평소 말로 물어보면 됩니다. 이런 요청에 스킬이 뜹니다.

- "이 앱 어떻게 돌아가?"
- "구조 그려줘."
- "이 기능, 다시 만들 수 있을 만큼 설명해줘."

에이전트는 REA를 돌리고, 증거와 한계를 단 주장을 기록하고, 원장 검증기를 돌린 뒤, 고정된 형식의 보고서를 돌려줍니다. REA와 분석 엔진(예: 네이티브 바이너리용 Ghidra)이 에이전트에 붙어 있을 때 가장 잘 동작합니다. 없으면 인용할 증거가 적어, 루프의 규칙에 따라 그 부분은 추측으로 채우는 대신 "unknown"으로 남습니다.
